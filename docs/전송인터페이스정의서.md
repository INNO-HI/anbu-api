# 전송 인터페이스 정의서 (SFR-006)

> 구현: [`src/anbu_api/transport/`](../src/anbu_api/transport/)

## 1. 프로토콜·보안
- **MQTT v5** (표준 게시·구독), QoS 1.
- 전송 구간 **TLS**(포트 8883, 브로커 CA 인증서 배포) — SFR-004 전송 암호화.
- 브로커: Eclipse Mosquitto(무상 라이선스), 본교 서버 내 운영.
- 구독 권한: 대학별 계정 + ACL(`anbu gen-acl`로 Subscription에서 생성).
  참여 대학은 **전송용 DB의 가명처리본만** 수신하며 원본 DB 접근 경로가 없다.

## 2. 토픽 구조

| 토픽 | 내용 | 방향 |
|---|---|---|
| `anbu/subjects` | 대상자(가명) | 본교 → 대학 |
| `anbu/devices` | 장비(가명) | 본교 → 대학 |
| `anbu/lighting_intervals` | 점등 구간 | 본교 → 대학 |
| `anbu/device_status_history` | 장비 상태 이력 | 본교 → 대학 |
| `anbu/care_records` | 돌봄 기록(자유기술은 SFR-010 채택 시에만) | 본교 → 대학 |
| `anbu/alerts` | 이상 알림 | 본교 → 대학 |
| `anbu/power_usage` | 전력 사용량(SFR-009 수행 시) | 본교 → 대학 |
| `anbu/receipts/<client_id>` | 수신 확인(제공 실적 집계용) | 대학 → 본교 |

## 3. 메시지 형식
- JSON(UTF-8), 1행 1메시지. 시각은 KST `YYYY-MM-DD HH:MM:SS`.
- 예시(`anbu/lighting_intervals`):
```json
{"id": 1, "pseudo_device_id": "f3a1…", "started_at": "2026-10-01 09:00:00",
 "ended_at": "2026-10-01 09:32:12", "duration_sec": 1944}
```
- 수신 확인(`anbu/receipts/univ_a`): `{"topic": "anbu/subjects", "record_count": 100}`
  — REST 경로 `POST /api/receipts`(X-Client-Id/X-Client-Key 헤더)도 동일 역할.

## 4. 전송 이력
- 발행 1회마다 `transfer_history`(테이블, 토픽, 건수, 상태, 발행자, 시각) 기록.
- 수신 확인은 `subscription_receipts`에 적재되어 대시보드 제공 실적 화면에 집계된다.

## 5. 참여 대학 수신 절차
1. 발주기관이 구독 등록(`POST /api/admin/subscriptions`) → `client_key` 1회 발급·전달.
2. 브로커 계정 발급(mosquitto_passwd) + ACL 재생성·반영.
3. 대학은 예제 코드([`subscriber_example.py`](../src/anbu_api/transport/subscriber_example.py))로 구독 수신.
4. 수신 후 관리 책임은 참여 대학에 있으며 보안 약정(재식별 금지, 목적 외 이용·제3자
   제공 금지, 기간 종료 시 파기·통보)을 준수한다.
