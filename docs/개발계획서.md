# 제주 안부똑똑 데이터 관리·전송 체계 구축 — 개발 계획서

> 본 문서는 **2026.10 개정 과업지시서**([PDF](./1.%20과업지시서_제주%20안부똑똑%20데이터%20관리·전송%20체계%20구축%20용역.pdf)) 기준이다.
> 구버전(수정본) 대비 변경: 사업금액·기간, 대금 지급 방식, 서버 사양·DB 규모 명시,
> 센서 162개(일 4.6만 행), SFR-010 과업 구성 제외, 하자보수 1년, 평가에 정량(신용) 5점 신설.

## 1. 사업 개요

| 항목 | 내용 |
|---|---|
| 사업명 | 제주 안부똑똑 데이터 관리·전송 체계 구축 용역 |
| 금액 | **13,970,000원** (부가세 포함) |
| 기간 | **계약 후 ~ 2026.12.20.** |
| 발주 | 동국대학교 COSS사업단 |
| 평가 | 기술 80%(정량 5 + 정성 75) + 가격 20% (기술 평점 68점 미만 부적격) |
| 대금 | **과업산출물 제출·검수 완료 후 일시 지급** |

**목적**: 제주 스마트 케어 실증에서 수집되는 IoT-LED 센서 데이터를 본교 서버에 누적 관리하고, 가명처리를 거쳐 참여 대학과 공유하며, 운영 현황을 실시간으로 확인하는 데이터 관리·전송 체계를 구축한다.

## 2. 현행 환경 분석 (개정판 명시 사항)

| 구분 | 현황 |
|---|---|
| 수집 대상 | 제주 지역 대상자 가구 — **대상자 78명**(테스트 계정 2개 별도) |
| LED 센서 | 방별 점등 기록. 점등 중 약 12초 간격 1행, 소등 중 무기록. **일평균 약 4.6만 행(센서 162개)** |
| 원시 로그 규모 | **약 69만 행**(2026.7.1 분석 기준) — 현재 규모는 SFR-001에서 확정 |
| 전력(AMI) | 테이블 2종, **0행(미적재)** → 제공 확보 시 SFR-009 |
| 원시스템 | 현장 돌봄 관리 시스템. **MariaDB 10.11, 31개 테이블**. 소스·저작권 원권리자 소유 |
| 적재 서버 | **HPE ProLiant DL360 Gen11(1U)** — Xeon Silver 4410Y(12C/24T, 2.0GHz), DDR5 ECC **128GB(현재 64GB, 보완 예정)**, **NVIDIA A2 16GB**, 960GB SSD |
| 저장 공간 | 메인 877GB 중 16GB 사용, **별도 저장 디스크 9.1TB 중 여유 8.6TB** |
| 누적 적재 | 단기 보관(약 3일) → 누적 구조 전환 운영 중 |
| 운영 대시보드 | 실시간 운영 대시보드 구축·운영 중 |

**시사점**
- NVIDIA A2 16GB 확보 → SFR-010 채택 시 소형 로컬 LLM 구동 여지(단, SFR-010은 과업 구성에서 제외됨).
- 데이터 디스크 여유 8.6TB, 일 4.6만 행(≈3.5MB/일) → 용량 압박은 낮으나 증설 시점 산정은 SFR-001 산식으로 정량화.
- 대상자 78명·테스트 계정 2개 → 테스트 계정은 전송본에서 제외하는 필터가 데이터 사전에 정의되어야 함.

## 3. 목표 시스템 아키텍처

```
원시스템(MariaDB 10.11) ─ETL─▶ 누적 DB(시계열) ─▶ 전송용 DB(가명 7테이블) ─┬▶ 참여 대학 MQTT/TLS 구독
 31개 테이블, 원본 보존        점등 구간·상태 이력·      무작위 토큰+암호화 매핑    └▶ 수신 확인 → 제공 실적
 (소스 수정 금지)             대상자 통합 뷰(v_subject_overview)
                                   └──▶ 실시간 운영 대시보드(SFR-005) · 3단계 권한·마스킹(SFR-007)
```

## 4. 과업 구성 변경점
- **SFR-001~009 필수/조건부 유지.**
- **SFR-010(자유기술 정밀 가명처리)은 과업 구성에서 제외** — 다만 가명처리 기준표·산출물에 "SFR-010 채택 시" 조항이 남아 있어, 발주기관 채택 시 즉시 수행 가능해야 함.
  본 구현은 모듈(freetext/)을 유지하되 기본 비활성(`--include-memo` 명시 시에만 동작)으로 대응한다.

## 5. SFR별 구현 (구현 완료 — 소스 매핑)

| SFR | 구현 위치 | 개정판 반영 사항 |
|---|---|---|
| 001 서버 진단 | `diagnostics/` | **기준 사양 대조표**(DL360 Gen11·24스레드·128GB·A2) 추가, 증가량 기준 4.6만 행/일 |
| 002 재구조화 | `etl/` | 점등 구간(증분·미완구간 보호), 상태 이력, 보존 정책, **대상자 통합 조회 뷰 `v_subject_overview`** |
| 003 데이터 사전 | `dictionary/` | 3개 DB 정의서(MD+CSV), 코드·결측 표준, 설치 현황, 알림 기준 |
| 004 가명처리 | `pseudonym/` | 무작위 토큰(단순 해시 금지)+Fernet 암호화 매핑 분리 보관, 연령대(85+ 통합)·읍면동·월단위·범주화 |
| 005 대시보드 | `api/` + 템플릿 | 적재·센서·전송·**제공 실적 집계** 4화면 |
| 006 구독 전송 | `transport/` | MQTT v5/TLS, 구독 권한 ACL 자동 생성, 전송 이력, 수신 확인(MQTT+REST) |
| 007 권한·마스킹 | `api/auth.py`, `masking.py` | 3단계(super_admin/admin/viewer), 매핑 재식별은 발주기관 전용+감사 로그 |
| 008 이관·교육 | `docs/운영매뉴얼.md` | 이관 체크리스트 포함 |
| 009 AMI(조건부) | `ami/` | 2종 통합(A 우선·중복 제거), 계량기 가명처리 |
| (010 채택 시) | `freetext/` | 규칙 기반 처리+재식별 시험(비율·건수만)+추가검수 — 기본 비활성 |

## 6. 공통 제약(개정판)
- 개인정보 데이터 본교 서버 밖 반출 금지, 외부 클라우드 AI 입력 불가.
- 원본 보존, 외부 제공은 합의 기준 가명처리본 한정. 수신 후 관리는 참여 대학 책임(보안 약정).
- 서버 접근 계정 한정·작업 이력 기록, 위탁 계약·보안 서약서.
- 원시스템 소스 수정·기능 변경 범위 제외. 참여 대학 교육용 가공·분석 환경 범위 제외.
- **무상 라이선스 도구 사용 원칙**(유상 협의 조항 삭제됨 → 전면 무상 구성: MariaDB·Mosquitto·Python 스택).
- 본교 지정 장소 작업 원칙, 원격은 승인 VPN·지정 단말·접속 기록.

## 7. 추진 일정 (계약 후 ~ 2026.12.20)

| 단계 | 기간(계약 후) | 주요 과업 | 산출물 |
|---|---|---|---|
| **1. 착수·진단** | 1~2주 | 수행계획서·보안 서약서, SFR-001 진단(사양 대조·증설 산정), SFR-003 원시스템 31테이블 분석 착수 | 수행계획서, 서버 진단 보고서 |
| **2. 재구조화·기준 합의** | 2~4주 | SFR-002(파생·이력·통합 뷰·보존정책), SFR-003 데이터 사전 완성, **SFR-004 가명처리 기준서 서면 합의** | DB 설계서, 보존정책서, 데이터 사전, 가명처리 기준서 |
| **3. 가명처리·전송 구축** | 4~6주 | SFR-004 전송용 DB·가명처리, SFR-006 MQTT 구독 전송·ACL, SFR-007 권한·마스킹, (확보 시)SFR-009 | 전송 인터페이스 정의서, 권한 정의서, 소스 |
| **4. 연계·검증·이관** | 6~8주 | SFR-005 대시보드 연계, 통합 테스트(적재 정합성·가명처리 점검·전송 확인), SFR-008 매뉴얼·교육·이관, 완료 보고 | 테스트 결과서, 매뉴얼, 교육자료, 운영 이관 계획서, 완료 보고서 |
| 예비 | ~12.20 | 검수 보완 대응 | — |

> **크리티컬 패스**: 가명처리 기준서 서면 합의(2단계)가 3단계의 선행 조건 — 착수 즉시 초안 제시.
> 참여 대학 데이터톤 일정 대응을 위해 3단계 종료 시점에 구독 전송 우선 개통.

## 8. 검수 및 하자보수 (개정)
