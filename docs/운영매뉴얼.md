# 사용자·운영 매뉴얼 (SFR-008)

운영 환경: 본교 다향관 서버. 모든 명령은 저장소 루트에서 실행한다.
`anbu` = `.venv/bin/python -m anbu_api.cli`

## 1. 최초 구축

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt && .venv/bin/pip install -e . --no-deps
cp .env.example .env            # 운영 값으로 수정(MariaDB URL, 비밀키, MQTT)
anbu init-db                    # 또는 db/migrations/*.sql을 MariaDB에 직접 적용
anbu create-user --username <발주기관담당자> --role super_admin
anbu create-user --username <운영담당자> --role admin
```

> `.env`의 `PSEUDONYM_SECRET_KEY`·`MAPPING_ENCRYPTION_KEY`는 발주기관이 생성·보관한다.
> 키를 분실하면 매핑 재식별이 불가능하고, 키가 바뀌면 기존 매핑과 호환되지 않는다.

## 2. 일상 운영 (정기 배치)

| 주기 | 명령 | 내용 |
|---|---|---|
| 매시 | `anbu etl intervals` | 원시 로그 → 점등 구간 파생(SFR-002) |
| 매시 | `anbu etl status` · `anbu etl inactivity` | 장비 상태 이력 적재·무신호 추론 |
| 일 1회 | `anbu pseudo-run` | 전송용 DB 가명처리 재구축(SFR-004) |
| 일 1회 | `anbu publish` | 참여 대학 구독 발행(SFR-006) — 사전 점검은 `--dry-run` |
| 월 1회 | `anbu etl retention` | 보존 정책 적용(보존정책서 참조) |
| (조건부) | `anbu ami-load` | 전력(AMI) 적재·통합(SFR-009, 데이터 제공 확보 시) |

cron 예시(`crontab -e`):
```cron
0 * * * *  cd /srv/anbu-api && .venv/bin/python -m anbu_api.cli etl intervals && .venv/bin/python -m anbu_api.cli etl status && .venv/bin/python -m anbu_api.cli etl inactivity
30 5 * * * cd /srv/anbu-api && .venv/bin/python -m anbu_api.cli pseudo-run && .venv/bin/python -m anbu_api.cli publish
0 6 1 * *  cd /srv/anbu-api && .venv/bin/python -m anbu_api.cli etl retention
```

## 3. 대시보드(SFR-005)

```bash
anbu serve --host 127.0.0.1 --port 8000     # 운영은 systemd 등록 권장
```
- 접속: `http://<서버>/dashboard` → 로그인 → 적재 현황 / 센서 동작 / 전송 현황 /
  데이터 제공 실적(참여 대학 구독 수신 집계) 확인.
- API 문서: `/docs` (OpenAPI).

## 4. 참여 대학 구독 등록(SFR-006)
1. 관리자 로그인 후 `POST /api/admin/subscriptions` (university, client_id, topic_pattern)
   → 응답의 `client_key`를 **1회만** 확인해 안전한 경로로 대학에 전달.
2. 브로커 계정 발급: `mosquitto_passwd /mosquitto/config/passwd <client_id>`
3. ACL 반영: `anbu gen-acl --out deploy/mosquitto/config/acl` 후 브로커 재적재.
4. 대학에 `subscriber_example.py`와 브로커 CA 인증서 전달.

## 5. 가명처리·재식별(SFR-004)
- 기준 변경은 `docs/가명처리기준서.md` 개정·서면 재합의 후 `rules.py` 반영.
- 적정성 검토 자료: `anbu pseudo-run --record build/가명처리결과기록.md`.
- 재식별(발주기관 전용): `GET /api/admin/mappings/resolve?namespace=subject&pseudo_id=…`
  (super_admin 토큰 필요, 전건 감사 로그 기록).

## 6. 자유기술 정밀 가명처리(SFR-010, 채택 시)
```bash
anbu pseudo-run --include-memo
anbu freetext-test --out build/재식별시험결과서.md \
  --review-sheet build/검수시트.csv --review-record build/추가검수기록.md
```
- 검수 시트의 플래그 메모를 사람이 검토·조치한 뒤 재실행·재시험한다.
- 한 사람으로 좁혀지는 메모가 있으면 해당 메모의 처리를 강화하고 재시험한다.

## 7. 서버 진단·데이터 사전
```bash
anbu diag --out build/서버진단보고서.md       # SFR-001
anbu dictionary --out-dir build              # SFR-003
```

## 8. 장애 대응
| 증상 | 확인 | 조치 |
|---|---|---|
| 발행 실패(error 이력) | 브로커 기동·TLS 인증서 | mosquitto 재시작 후 `anbu publish` 재실행 |
| 구간 미생성 | 원시 로그 적재 여부, `LIGHTING_GAP_THRESHOLD_SEC` | 적재 경로 점검 후 `anbu etl intervals` |
| 로그인 불가 | 계정 active 여부 | super_admin이 계정 재발급 |
| 디스크 임박 | `anbu diag` 증설 시점 | 보존 정책 단축 협의 또는 증설 |
