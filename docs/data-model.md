# 데이터 모델 및 가명처리 기준

> 전송용 DB 7개 테이블과 가명처리 기준(SFR-004). 실제 컬럼·코드값은 SFR-003 데이터 사전 작성 결과로 확정한다. 아래는 과업지시서 기준의 설계 초안이다.

## 1. 전송용 DB 테이블 (7개)

원본 DB와 **물리적으로 분리**하며, 참여 대학은 원본 DB에 직접 접근하지 않는다.

| # | 테이블 | 설명 | 비고 |
|---|---|---|---|
| 1 | 대상자 | 대상자 단위 기본 정보 | 직접식별자 삭제, 가명 식별자 부여 |
| 2 | 장비 | 센서/장비 정보 | 가명 장비 식별자 |
| 3 | 점등 구간 | LED 점등 구간(시작·종료·지속 시간) | SFR-002 파생 테이블 기반 |
| 4 | 장비 상태 이력 | 정상/비활성/장애 변경 이력 | 무활동 vs 장비 중단 구분 |
| 5 | 돌봄 기록 | 현장 돌봄 기록 | 자유기술 항목은 전송 제외(SFR-010 채택 시 예외) |
| 6 | 이상 알림 | 이상 알림 이벤트 | 이상 알림 기준은 데이터 사전 반영 |
| 7 | 전력 사용량 | 시간 단위 전력(AMI) | **SFR-009 수행 시에만** 포함 |

## 2. 가명처리 기준 (가명처리 기준서 초안)

> 발주기관과 **서면 합의 후 적용**. 기준서에 아래 항목을 포함한다.

| 구분 | 기준 |
|---|---|
| 직접식별자 | 이름, 연락처, 주소, 보호자·담당자 정보 **삭제** |
| 가명 식별자 | 대상자·장비·계량기 식별자를 **무작위 또는 비밀키 기반** 가명 식별자로 치환. **단순 해시 방식 미사용** |
| 준식별자 | 생년월일 → **연령대**로 일반화(85세 이상 단일 범주 통합). 지역 → **읍·면·동 단위까지만** 유지(이하 세부 주소 삭제) |
| 서비스 시작/종료일 | **월 단위(연·월)** 로 변환 |
| 내부 일련번호 | 원본 DB 내부 일련번호 → 전송본에서 **새 키로 대체** |
| 자유기술 항목 | **전송 제외**. 발주기관이 허용하고 SFR-010 채택 시에만 SFR-010 처리 + 추가 검수 후 전송 |
| 건강·경제 상태 | 식사·인지·의사소통 기능: 단계값을 상위 범주(자립/부분 도움/전적 도움)로 **범주화**. 수급 구분: **삭제**(필요 시 협의하여 수급 여부 예/아니오만). 고위험군 여부: 예/아니오만 제공, 판정 사유 삭제. **건강 항목은 민감정보** → 제공 근거·추가 안전조치를 기준서에 기재하고 발주기관과 협의 확정 |

## 3. 매핑 테이블 (원 식별자 ↔ 가명 식별자)
- **암호화**하여 원본과 **분리 보관**.
- **발주기관 전용 권한**으로만 접근(SFR-007).
- 재식별은 발주기관의 적정성 검토·처리 기록 목적에 한함.

## 4. 가명 식별자 생성 방식 (권장)
과업지시서 요구("단순 해시 미사용")에 따라 다음 중 택일/병용한다.

1. **무작위 토큰 + 매핑 테이블**(권장): 원 식별자별 랜덤 UUID/토큰을 발급해 전송본에 사용하고, 원↔가명 대응은 암호화된 매핑 테이블에만 보관. 전송본만으로는 역추적 불가.
2. **비밀키 기반 토큰화**: 비밀키(HMAC 등)로 결정적 치환하되 키는 발주기관 전용 보관. 단순 해시(키 없는 해시)는 사용하지 않음.

> 구현 참조: [`../src/anbu_api/pseudonymize.py`](../src/anbu_api/pseudonymize.py)

## 5. 전송(구독) 설계 (SFR-006)
- 프로토콜: **MQTT(TLS)**. 토픽 예시: `anbu/{dataset}/{table}`.
- 참여 대학별 **구독 권한(ACL)** 관리, 토픽 단위 구독.
- 전송 이력(수신 주체·시각·건수) 기록 → SFR-005 제공 실적 집계 화면과 연계.
