# 가명처리 기준서 (SFR-004)

> 본 기준서는 발주기관과 **서면 합의 후** 적용한다. 구현 단일 원천:
> [`src/anbu_api/pseudonym/rules.py`](../src/anbu_api/pseudonym/rules.py),
> [`mapping_store.py`](../src/anbu_api/pseudonym/mapping_store.py),
> [`engine.py`](../src/anbu_api/pseudonym/engine.py)

| 구분 | 기준 | 구현 |
|---|---|---|
| 직접식별자 | 이름, 연락처, 주소, 보호자, 담당자 정보 삭제 | 전송용 스키마에 해당 컬럼이 존재하지 않음(구조적 차단) |
| 가명 식별자 | 대상자·장비·계량기 식별자를 무작위 또는 비밀키 기반으로 치환, **단순 해시 미사용** | `secrets` 무작위 토큰 + HMAC-SHA256 조회키(비밀키 기반). 전송본만으로 역산 불가 |
| 준식별자(생년월일) | 연령대로 일반화, **85세 이상 단일 범주 통합** | 5세 구간(65-69…80-84), 85세 이상 `85+`, 65세 미만 통합 |
| 준식별자(지역) | 읍·면·동 단위까지만 유지, 세부 주소 삭제 | `region_emd`만 전송, `address_full` 비전송 |
| 서비스 시작·종료일 | 월 단위(연·월) 변환 | `YYYY-MM` 문자열 |
| 내부 일련번호 | 전송본에서 새 키로 대체 | 전송 테이블 PK는 원본과 무관한 autoincrement |
| 자유기술 항목 | 전송 제외. 발주기관 허용 + SFR-010 채택 시에만 정밀 가명처리·추가검수 후 전송 | `memo_pseudo` 기본 NULL, `--include-memo` 채택 시에만 |
| 건강 상태(기능 단계) | 상위 범주화(자립/부분 도움/전적 도움) | L1~L2→자립, L3~L4→부분도움, L5→전적도움 |
| 경제 상태(수급 구분) | 삭제. 연구 필요 시 발주기관 협의로 예/아니오만 | `benefit_yn` 기본 NULL |
| 고위험군 | 예/아니오만 제공, 판정 사유 삭제 | `high_risk_yn`만 전송 |

## 매핑 테이블 관리 방안
- 원 식별자는 **Fernet 암호화**해 저장(평문 저장 금지), 운영 DB에 원본·전송용과 **분리 보관**.
- 접근은 **발주기관 전용 권한(super_admin)** 의 재식별 API로만 하며 전건 감사 로그를 남긴다.
- 암호화 키·비밀키는 환경변수로만 주입하고 발주기관이 보관한다(리포지토리 커밋 금지).

## 민감정보(건강 관련 항목) 추가 안전조치
- 제공 근거: 「개인정보 보호법」 가명정보 처리 특례(과학적 연구 목적).
- 범주화로 식별력을 낮추고, 판정 사유 등 서술형 정보는 전송하지 않는다.
- 제공 범위 변경은 본 기준서 개정·재합의 후에만 적용한다.
