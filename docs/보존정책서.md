# 누적 DB 보존정책서 (SFR-002)

> 구현: [`src/anbu_api/etl/retention.py`](../src/anbu_api/etl/retention.py)
> (환경변수 `RETENTION_RAW_LOG_DAYS`로 보존 일수 조정)

**저장 환경(2026.10 개정 과업지시서)**: 메인 960GB SSD(877GB 중 16GB 사용) +
별도 저장 디스크 9.1TB(여유 8.6TB). 일평균 약 4.6만 행(≈3.5MB/일) 기준으로 용량
여유는 충분하나, 증설 시점은 SFR-001 진단 산식으로 정기 재산정한다.

| 데이터 | 보존 기간 | 기간 경과 시 | 근거 |
|---|---|---|---|
| LED 원시 로그(led_raw_logs) | **365일** | 파기(DELETE) | 점등 구간 파생 테이블이 분석용 요약을 장기 보존하므로 원시 행 파기 가능 |
| 점등 구간(lighting_intervals) | 사업·연구 기간 | 보존 | 대상자 생활 패턴 분석의 기본 단위 |
| 장비 상태 이력(device_status_history) | 사업·연구 기간 | 보존 | 무활동/장비중단 구간의 사후 구분 근거 |
| 돌봄 기록·이상 알림 | 사업·연구 기간 | 보존 | 서비스 운영·연구 근거 |
| 전력(AMI) 정본(power_usage) | 사업·연구 기간 | 보존 | SFR-009 통합 정본 |
| 가명 매핑(pseudonym_mappings) | 가명정보 이용 기간 | 이용 종료 시 파기 | 가명정보 처리 특례 — 재식별 수단의 분리·파기 |

## 운영 절차
1. 보존 정책 적용은 월 1회 정기 실행: `anbu etl retention` (cron 등록, 운영매뉴얼 참조).
2. 파기 결과(건수·기준 시각)는 실행 기록(EtlRun)으로 남는다.
3. 보존 기간 변경은 발주기관 협의 후 `.env` 수정과 본 문서 개정을 함께 한다.
4. 대상자 서비스 종료·동의 철회 시 개별 파기는 발주기관 요청에 따라 수행한다.
